# Пивной надзор 💪🍺

Telegram-бот для вашей компании: кружки и видео, ежедневные отметки в существующей Google-таблице, напоминания и пивные долги. Python, aiogram 3, Dishka, ARQ, Redis, uv и Docker Compose.

## Правила

- День принимается до **23:59 включительно по Москве**. Закрытие — в 00:00 следующего дня.
- В **13:00** бот тегает тех, кто ещё не сделал. В **18:00** публикует текущие итоги; это не закрытие дня.
- Принимаются собственные кружки или видео **от 50 секунд до 10 минут**. Длительность настраивается. Пересылки и повтор уже засчитанного Telegram `file_unique_id` отклоняются.
- На реплай боту или сообщение с его @упоминанием бот распознаёт русские просьбы выполнить команду с датой, участником и причиной. Проверки прав, сроков и дедупликация те же, что у команд через меню. Обычный текст получает короткую шутку локальной нейросети: сначала появляется «🧠 Думаю» с вращающимся индикатором, затем то же сообщение заменяется ответом. Видео, активные и истёкшие запросы даты/причины обрабатываются отдельно.
- Бот проверяет отправителя, тип и длительность. **Содержание видео и технику отжиманий он не распознаёт.** Видео файлом без Telegram-метаданных длительности нужно отправить как видео.
- За каждый пропуск — **по одному пиву каждому другому участнику**. Если оба пропустили, оба должны друг другу. Взаимозачёта нет. Стартовые штрафы из таблицы сохраняются.
- Уважительную причину подтверждает Ярик; причины сохраняются в примечании к отметке и журнале.
- Участники — четыре человека из столбцов C:F листа «Ежедневно», связанные с блоком «Пользователи» листа «Сводка». Остальные люди в чате автоматически участниками не становятся. При изменении структуры таблицы адаптер останавливается с ошибкой вместо записи не туда.

## Подключение в Telegram

1. Именно **@yarvod, Telegram ID 718724903** добавляет бота в группу.
2. Дайте боту статус администратора без прав удаления, блокировки и назначения администраторов: это позволяет видеть видео. Альтернатива — отключить Group Privacy через BotFather и заново добавить бота. Для 🍾 в группе должна быть разрешена эта реакция. Кружки 🍻 добавляются в текст подтверждения: Telegram не поддерживает 🍻/🍺 как обычные реакции, только как отдельно настроенные кастомные эмодзи.
3. Ярик отправляет `/setup` в группе. До этого бот не ведёт учёт и не рассылает напоминания.
4. Первый ролик или ручная отметка связывает username из таблицы с постоянным Telegram ID. Ярик может заранее связать участников через `/bind @username 123456789`.

Telegram не позволяет запретить саму попытку добавления бота чужим пользователем. При чужом
приглашении бот ждёт до 10 секунд служебное подтверждение преобразования уже разрешённой группы
в супергруппу; если подтверждения нет — выходит. `/setup` доступна только числовому ID владельца.
Назначать бота администратором и менять его права в уже добавленной беседе может любой её админ.
При преобразовании группы бот переносит разрешение владельца и подключение на новый ID.
Это работает и до успешного `/setup`. Подключается одна группа; для переноса в другую беседу
сначала `/unbind` в старой.

## Команды

Нажатие команды в Telegram отправляет её сразу. Для `/done`, `/miss` и `/excuse` без аргументов
бот открывает ответ на подсказку: впишите дату и причину или «сегодня». Полную команду с аргументами
по-прежнему можно отправить одним сообщением. Поддерживаются даты `09.09.2026` и `2026-09-09`;
невалидная дата вызывает ошибку, а не становится причиной за сегодня. Запрос принадлежит автору,
хранится сутки в Redis и отменяется ответом «отмена». После выполнения повторный ответ не меняет отметку.
Если сначала указать только дату, бот попросит дописать причину. Повторная отметка тем же статусом
обновляет причину и тоже получает подтверждение.

Список команд регистрируется в Telegram при каждом запуске бота и появляется при вводе `/`.
Команды владельца подписаны «только Ярик»; видимость в меню не даёт права выполнять их.

| Команда | Действие |
| --- | --- |
| `/help` | Правила и помощь |
| `/today` | Отметки за сегодня |
| `/stats` | Сделано, уважительные причины, пропуски и общий долг |
| `/debts` | Направленные долги «кто → кому» |
| `/sheet` | Ссылка на таблицу |
| `/done`, `/miss`, `/excuse` | Бот попросит дату / причину ответным сообщением; до ответа ничего не записывает |
| `/done сегодня` | Отметить себя за сегодня до дедлайна |
| `/miss сегодня` | Отметить собственный пропуск |
| `/excuse заболел` | Отметить себе уважительную причину за сегодня до дедлайна |
| `/done @weebat 2026-09-05 исправление` | Владелец исправляет участника и дату |
| `/miss @weebat 2026-09-05` | Владелец отмечает пропуск |
| `/excuse @weebat 2026-09-05 болеет` | Владелец подтверждает уважительную причину |
| `/excuse 09.09.2026 командировка` | Владелец отмечает себе уважительную причину за прошлую дату |
| `/bind @weebat 123456789` | Владелец меняет привязку Telegram ID |
| `/setup`, `/unbind` | Владелец подключает / отключает группу |

Дата и username для владельца необязательны: по умолчанию сегодня и он сам. Для остальных доступны только собственные сегодняшние `/done`, `/miss` и `/excuse причина` до дедлайна. Для `/excuse` текст причины обязателен; она сохраняется в таблице и журнале, за уважительный пропуск пиво не начисляется. Записи в Google Sheets можно исправлять напрямую; бот читает их при следующих запросах. Такие прямые исправления видны в истории Google, но не в журнале команд бота.

## Настройки

Скопируйте `.env.example` в `.env`, если `.env` ещё не существует. Не перезаписывайте уже сохранённый токен.

| Переменная | По умолчанию |
| --- | --- |
| `TOKEN` | Секрет BotFather, обязательный |
| `OWNER_ID` | `718724903` |
| `SPREADSHEET_ID` | ID вашей таблицы |
| `TIMEZONE` | `Europe/Moscow` |
| `DEADLINE_TIME` | `23:59`, последняя принимаемая минута |
| `REMINDER_TIME` | `13:00` |
| `SUMMARY_TIME` | `18:00` |
| `MIN_VIDEO_SECONDS` / `MAX_VIDEO_SECONDS` | `50` / `600` |
| `GOOGLE_APPLICATION_CREDENTIALS` | `secrets/google-service-account.json` |
| `REDIS_URL` | `redis://localhost:6379/0`; Compose задаёт свой адрес |

Время — `HH:MM`, без секунд. После изменения `.env`: `docker compose up -d --force-recreate bot worker`. Воркер синхронизирует часовой пояс и формулы таблицы при запуске. Чтобы настройки совпадали, не меняйте расписание вручную на служебном листе.

## Google Cloud

Используется отдельный сервисный аккаунт `pullups-bot@yoowee-chat-prod.iam.gserviceaccount.com` без IAM-ролей на проект. Включён Google Sheets API; аккаунту выдан доступ редактора только к предоставленной таблице. Ключ хранится в `secrets/google-service-account.json`, не попадает в Git или образ Docker.

Для нового окружения нужны Sheets API, сервисный аккаунт, его JSON-ключ и доступ редактора к таблице. Cloud SQL, Firestore и Google Drive API боту не нужны.

```sh
uv sync --frozen
uv run python scripts/admin.py doctor
uv run python scripts/admin.py backup
uv run python scripts/admin.py init
```

`init` идемпотентен: сохраняет отметки, комментарии, стартовые штрафы и оформление; обновляет формулы дедлайна и добавляет «Бот — настройки» и «Бот — журнал». В журнале — автор, старый/новый статус, причина, ссылка-идентификатор сообщения и ключ события. При старте воркер делает `init` автоматически. Перед первым запуском используйте `backup`: полный снимок Google Sheets сохраняется локально в исключённую из Git папку `backups/`. Для пользовательского отката отметок также есть история версий Google Sheets.

## Запуск и ручной деплой

### Локальные ответы на реплаи

Используется [Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B) в формате GGUF Q4_K_M (около 397 МБ на диске, квантизация Unsloth). Режим рассуждений отключён: нужен короткий ответ, а не объяснение шутки. Русские формулировки команд разбираются отдельно, без нейросети: на этом сервере Qwen не уложилась в 30 секунд на коротком запросе с JSON, а Needle3 на проверочных фразах путала шутку и долги с командой помощи. Разбор ограничен явными формулировками; неузнанный запрос идёт в обычный ответ. Для записи отметок и настроек используются существующие обработчики с их проверками прав.

`llm` запускает llama.cpp только во внутренней сети Compose: внешний порт и API-ключ не нужны. Лимиты — 640 МБ памяти без swap и 0,75 ядра, один поток и одна генерация одновременно. Модель ничего не записывает в таблицу и не получает токен Telegram или Google credentials. В запрос попадает только текущая реплика (до 240 символов): цитата, история беседы и готовые примеры шуток модели не передаются. Промпт — одна короткая инструкция шутить дерзко по-русски с матом и сарказмом.

Отдельный ARQ-процесс `banter` обслуживает очередь `pushups:banter`, поэтому медленная генерация не задерживает команды, видео и расписание основного worker. Анимация обновляется раз в 2,5 секунды. Через 25 секунд ожидания, при недоступности модели, пустом или оборванном ответе и типовых отписках сообщение заменяется текстом «Думал, думал, но не смог придумать ответ 😅 Попробуй ещё раз». Если первый ответ не годится, бот пробует получить другой в пределах тех же 25 секунд; законченную первую фразу сохраняет, даже если генерация оборвала последующую. Вступления вроде «Конечно, вот шутка для тебя» удаляются, а не публикуются вместо шутки. Повторная доставка задачи переиспользует сообщение и уже полученный ответ.

`scripts/download_model.sh` скачивает закреплённую версию весов и проверяет SHA256. Каталог `models/` исключён из Git и Docker build context. Деплой вызывает этот скрипт автоматически. Стиль задаётся в `infrastructure/banter.py`; срок ожидания, длина и творческая случайность ответа задаются в Compose — `LLM_TIMEOUT_SECONDS` (25), `LLM_MAX_TOKENS` (40) и `LLM_TEMPERATURE` (0,8). Более высокие значения температуры делают ответ менее предсказуемым; слишком высокий уровень ухудшает связность у этой маленькой модели. Во время генерации CPU занят до установленного лимита. Низкий `cpu_shares` отдаёт приоритет остальным сервисам при конкуренции за CPU.

```sh
bash scripts/download_model.sh
docker compose up -d --build --wait
docker compose logs --tail=30 banter llm
```

На сервере проект размещается в **`/root/pullups-bot`**, отдельный Compose project `pullups-bot`. Порты на хост не публикуются; существующие сервисы не затрагиваются.

После загрузки репозитория и двух секретных файлов:

```sh
cd /root/pullups-bot
chmod 600 .env
chown root:10001 secrets/google-service-account.json
chmod 440 secrets/google-service-account.json
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 bot worker
```

Приложение работает внутри контейнеров как UID 10001, файловая система доступна только для чтения. Redis использует отдельный постоянный том и AOF с `appendfsync always`. Токен передаётся окружением при запуске; не печатайте `docker compose config` без `--quiet` и полный `docker inspect` — они могут раскрыть его.

Код хранится в [yarvod/push_ups_bot](https://github.com/yarvod/push_ups_bot), ветка `main`.
Локальный и серверный `origin` используют SSH: `git@github.com:yarvod/push_ups_bot.git`.
На сервере используется уже добавленный пользователем SSH-ключ с доступом к репозиторию.
Секреты исключены из Git и остаются отдельно на каждом компьютере.

После локальных изменений, проверок и коммита:

```sh
git push origin main
ssh nl 'cd /root/pullups-bot && bash scripts/deploy.sh'
```

Или прямо на сервере:

```sh
cd /root/pullups-bot
bash scripts/deploy.sh
```

Скрипт получает `main` через `git pull --ff-only`, проверяет Compose без вывода секретов,
собирает образ и ждёт успешных проверок здоровья. Если есть незакоммиченные изменения,
другая ветка или разошедшаяся история, он останавливается. Серверные `.env`, `secrets/`
и том Redis сохраняются. Автоматический деплой по push пока не включён — запуск ручной.

Если правили код на сервере, сначала перенесите эти изменения в Git отдельным коммитом;
основной рабочий процесс — разработка локально и получение готовых коммитов сервером.
Откат кода: выбрать предыдущий коммит и выполнить `docker compose up -d --build` напрямую.
Не выполняйте `docker compose down -v`: это удалит очередь Redis.
Обычный `docker compose down` сохраняет том.

Для запуска на компьютере с Redis:

```sh
uv run python -m pullups_bot
# В другом терминале:
uv run arq pullups_bot.worker.WorkerSettings --custom-log-dict pullups_bot.logging_config.LOGGING
```

Одновременно должен работать только один poller, один основной worker и один banter-worker. Масштабирование для чата из четырёх человек не требуется.

## Надёжность и ограничения

- Poller сначала сохраняет обновление Telegram в Redis и лишь затем подтверждает его Telegram. ARQ обрабатывает сообщения по очереди, повторяя временные ошибки API.
- Изменение статуса и запись в журнал коммитятся одним атомарным Google batch. Повтор события не начисляет новые долги. Отдельная Redis-блокировка сериализует записи и продлевается во время запросов.
- ARQ каждую минуту проверяет расписание. После перезапуска закрывает незавершённые дни с момента активации; даты при необходимости продлевает на месяц вперёд. Существующие отметки ✅ и 🟡 не затираются.
- Видео, отправленное до дедлайна, относится к дате отправки, даже если очередь обработала его после полуночи.
- Напоминание догоняется максимум на 2 часа, вечерняя сводка — до конца текущего дня. Маркеры отправки сохранены в таблице. При обрыве ровно между отправкой Telegram и сохранением маркера возможен повтор сообщения: Telegram не даёт транзакцию вместе с Sheets.
- Telegram хранит неполученные обновления ограниченное время (до 24 часов). Длительный простой самого poller требует ручных исправлений. Ранее поставленные в Redis задачи живут до 7 дней, результаты — 7 дней; сохраняйте Redis-том.
- Sheets не даёт совместной блокировки с ручным редактированием человеком. Не редактируйте ту же ячейку одновременно с командой бота. Ошибочный статус можно исправить; полная история остаётся в Google Sheets.

## Архитектура и проверки

`domain` содержит статусы и правила долгов, `application` — сценарии и интерфейсы хранилища/блокировки, `infrastructure` — адаптеры Sheets и Redis, `presentation` — aiogram-команды и тексты. Dishka собирает зависимости; транспорт Telegram и Google API не импортируются в предметную логику. ARQ запускает обработку сообщений и расписание.

```sh
uv run pytest -q
uv run ruff check src tests scripts
uv run ruff format --check src tests scripts
uv run mypy src
```

Тесты используют подставные Telegram/Sheets-адаптеры без настоящего токена. Проверяются долги без взаимозачёта, стартовые штрафы, граница суток, права владельца, повторные видео, уважительные причины, восстановление дней, реальная связка aiogram + Dishka и расписание.

Документация библиотек: [aiogram / Telegram API](https://core.telegram.org/bots/api), [Dishka](https://dishka.readthedocs.io/en/stable/integrations/aiogram.html), [ARQ](https://arq-docs.helpmanual.io/).
